1  왜 거대언어모델(LLM) 하나로는 엔터프라이즈 문제를 풀 수 없는가?

생성형 AI와 거대언어모델(LLM)이 산업계의 모든 기술 의제를 집어삼킨 듯한 시기다. 기업의 기술 전략 회의나 국가 R&D 과제 평가 현장에 들어가 보면, 기존에 잘 작동하던 시계열 예측 모델이나 이상탐지 파이프라인까지 모두 걷어내고 그 자리에 범용 LLM이나 에이전트를 단독으로 배치하겠다는 제안서를 어렵지 않게 마주한다. 정형 데이터베이스의 수치 행(Row)들을 텍스트로 변환해 프롬프트에 밀어 넣으면, 별도의 피처 엔지니어링(Feature Engineering)이나 모델 학습 없이도 예측과 이상 감지가 가능할 것이라는 기대다.

결론부터 말하면, 이러한 ’단일 모델 만능주의(Monolithic LLM Fallacy)’는 프로덕션 환경에 진입하는 순간 세 가지 물리적 장벽에 부딪혀 좌초한다. 첫째는 정형·수치 데이터 공간에서 트랜스포머(Transformer)가 가지는 귀납적 편향(Inductive Bias)의 한계이고, 둘째는 자기회귀(Autoregressive) 토큰 생성 구조가 유발하는 연산 비용과 지연시간(Latency)의 폭발이며, 셋째는 다단계 추론 시 기하급수적으로 누적되는 확률적 환각(Hallucination)이다.

엔터프라이즈 환경에서 에이전트 아키텍처를 올바로 설계하려면, 먼저 LLM이 무엇을 할 수 없는지 수리적·공학적으로 규정해야 한다. 본 장에서는 전통적인 판별·예측 모델(머신러닝 및 도메인 특화 딥러닝)이 왜 여전히 대체 불가능한지 학술적 근거를 통해 규명하고, 단일 거대 모델에서 복합 AI 시스템(Compound AI Systems)으로 이동해야만 하는 아키텍처적 필연성을 다룬다.

1.1 정형·시계열 데이터의 물리학: 왜 트리 모델과 특화 모델은 여전히 압도적인가?

자연어와 이미지, 코드 생성 영역에서 트랜스포머 기반 파운데이션 모델이 기존 알고리즘을 평정한 것과 달리, 기업 데이터의 80% 이상을 차지하는 정형 데이터(Tabular Data)와 고주파 시계열(Time-series) 영역에서는 여전히 그래디언트 부스팅 트리(LightGBM, XGBoost, CatBoost)나 오토인코더(Autoencoder) 계열의 특화 모델이 최상위 성능을 유지하고 있다.

이 현상은 단순한 경험칙이 아니다. Grinsztajn et al.(2022)은 NeurIPS에 발표한 연구(“Why do tree-based models still outperform deep learning on typical tabular data?”)에서 45개의 실제 정형 데이터셋을 대상으로 하이퍼파라미터 탐색에 총 2만 시간 이상의 연산 자원을 투입하여 트리 기반 모델과 최신 딥러닝(ResNet, FT-Transformer 등)을 엄밀하게 비교했다. 실험 결과, 중간 규모(샘플 수 1만 개 내외)의 정형 데이터셋 전반에서 트리 기반 모델이 일관되게 높은 정확도와 압도적으로 낮은 연산 비용을 기록했다. 연구진이 규명한 근본 원인은 신경망 아키텍처가 가진 고유한 성질과 정형 데이터의 기하학적 특성 간의 불일치에 있다.

1.1.1 불규칙한 결정 경계(Irregular Decision Boundaries)와 과도한 평활화

심층 신경망(Deep Neural Networks)은 경사하강법(Gradient Descent)을 통해 파라미터를 최적화하는 구조적 특성상, 저주파 함수(Low-frequency functions)에 편향되어 있으며 입력 공간에서 매끄럽고 연속적인 함수(Smooth functions)를 학습하려는 경향이 강하다. 자연어나 이미지에서는 픽셀이나 문맥의 연속성이 전제되므로 이러한 평활화(Smoothing) 성질이 일반화 성능을 높이는 강력한 무기가 된다.

반면, 현업의 정형 데이터와 센서 로그는 본질적으로 불연속적이다. 예를 들어 통신망 기지국의 트래픽 장애 임계치나 금융 거래의 이상 징후, 환자의 생체 신호 위험 구간은 특정 수치 하나가 기준점을 넘는 순간 상태가 급변하는 계단 함수(Step function) 형태의 날카롭고 불규칙한 결정 경계를 가진다. 좌표축에 평행하게 공간을 분할(Axis-aligned split)하는 결정 트리 계열 모델은 이러한 불연속적 경계를 손실 없이 포착하지만, 신경망과 LLM은 경계면을 매끄럽게 뭉개버리면서 미세한 이상 징후(Outlier)를 놓치게 된다.

1.1.2 불필요한 피처(Uninformative Features)와 회전 불변성(Rotational Invariance)

실무 데이터셋에는 타깃 변수와 무관한 노이즈 피처나 다중공선성(Multicollinearity)을 띤 컬럼이 다수 포함된다. Grinsztajn et al.(2022)은 데이터셋에서 불필요한 피처를 제거할수록 트리 모델과 신경망 간의 성능 격차가 줄어들고, 반대로 무관한 노이즈 피처를 추가할수록 신경망의 성능이 급격히 붕괴함을 실험으로 증명했다.

그 원인은 다층 퍼셉트론(MLP)과 어텐션 계층이 가진 회전 불변성(Rotational Invariance)에 있다. 입력 벡터 \(x \in \mathbb{R}^d\)에 대해 직교 행렬(Orthogonal Matrix) \(Q\)를 곱해 데이터 공간을 회전시켜도 신경망의 학습 역학은 본질적으로 동일하게 작동한다. 문제는 정형 데이터의 각 컬럼(예: 나이, CPU_사용률, 결제_금액)은 서로 단위가 다르고 고유한 물리적 의미를 지니고 있어, 이를 선형 결합(Linear Combination)하여 회전시키는 순간 원래 피처가 가진 정보의 독립성이 훼손된다는 점이다. 트리 모델은 정보 이득(Information Gain)이 없는 피처를 분할 후보에서 단순히 배제함으로써 노이즈에 강건하지만, 모든 입력 토큰과 차원을 밀집 벡터(Dense Vector)로 투영해 섞어버리는 아키텍처는 노이즈 피처의 간섭에 취약할 수밖에 없다.

1.1.3 수치의 토큰화(Tokenization)와 자기회귀 연산의 한계

정형 데이터나 시계열 수치를 LLM에 직접 입력할 때 발생하는 또 다른 치명적 문제는 토큰화(Tokenization) 과정에서 발생하는 수리적 위상 손실이다. BPE(Byte-Pair Encoding) 계열의 토크나이저는 숫자 1024.58을 하나의 연속적인 실수(Float)로 인식하지 않고, ["102", "4", ".", "58"]과 같은 이산적 문자열 조각(Subword token)으로 쪼갠다.

Dziri et al.(2023)이 NeurIPS에서 발표한 연구(“Faith and Fate: Limits of Transformers on Compositionality”)에 따르면, 트랜스포머의 다음 토큰 예측(Next-token prediction) 메커니즘은 다단계 산술 연산이나 복합 함수 추론에서 입력 길이가 길어질수록 정답률이 지수적으로 하락한다. 모델이 실제 수리적 알고리즘을 수행하는 것이 아니라 학습 데이터에 존재하는 표면적 패턴 매칭(Subgraph matching)에 의존하기 때문이다. 수천 개의 시계열 센서 값에서 평균과 분산을 계산하거나 다변량 공분산 구조의 이탈 정도(예: 오토인코더의 재구성 오차 \(L = \Vert{}x - \hat{x}\Vert{}_2^2\))를 판별하는 작업을 텍스트 생성 모델에게 맡기는 것은 공학적으로 가장 비효율적인 선택이다.

귀납적 편향(Inductive Bias)의 관점에서 본 역할 분담

데이터 사이언티스트에게 익숙한 ‘공짜 점심은 없다(No Free Lunch Theorem)’ 정리는 에이전트 시대에도 그대로 적용된다. - 전통적 ML/DL (LightGBM, Autoencoder 등): 고정된 스키마의 정형·수치 공간 \(\mathcal{X} \subset \mathbb{R}^d\)에서 조건부 확률 \(P(Y\vert{}X)\)를 추정하거나 정상 데이터의 잠재 다양체(Manifold)를 학습하는 데 최적화된 귀납적 편향을 가진다. - LLM 및 에이전트: 비정형 텍스트 공간에서 의미론적 맥락(Semantic Context)을 연결하고, 이질적인 정보원(매뉴얼, 로그 설명, API 명세)을 조합해 행동 계획(Action Plan)을 수립하는 데 최적화되어 있다.

따라서 LLM은 기존 예측 모델을 ’대체’하는 상위 모델이 아니라, 예측 모델이 출력한 확률값과 피처 기여도를 입력받아 후속 의사결정을 수행하는 오케스트레이션 계층(Orchestration Layer)으로 정의해야 한다.

1.2 비용과 지연시간의 경제학: 실시간 스트림에 LLM을 직결할 때 벌어지는 일

설령 프롬프트 엔지니어링이나 파인튜닝을 통해 LLM이 정형 데이터 분류에서 기존 모델과 유사한 정확도를 달성했다고 가정해 보자. 그래도 엔터프라이즈 프로덕션에서는 이 모델을 실시간 데이터 스트림의 전면에 배치할 수 없다. 처리량(Throughput)과 지연시간(Latency), 그리고 추론 비용의 스케일링 법칙이 전혀 다르기 때문이다.

초당 500건의 트랜잭션이나 장비 로그가 발생하는 중규모 시스템을 가정하자. 하루에 발생하는 이벤트 수는 다음과 같다.

\[N_{\text{daily}} = 500 \text{ events/sec} \times 86,400 \text{ sec/day} = 43,200,000 \text{ events/day}\]

하나의 이벤트를 판별하기 위해 500 토큰의 시스템 프롬프트 및 피처 텍스트를 입력하고 100 토큰의 추론 결과를 생성한다면, 일일 총 토큰 소모량은 입력 216억 토큰, 출력 43.2억 토큰에 달한다. Chen et al.(2023)이 FrugalGPT 연구에서 지적했듯, 고빈도 루틴 작업에 프론티어 LLM을 무차별 호출하는 구조는 기업의 클라우드 예산을 수일 내에 고갈시킨다.

아래 파이썬 코드는 동일한 1만 건의 다변량 정형 데이터 스트림에서 이상 징후를 탐지할 때, 전통적인 머신러닝/딥러닝 파이프라인과 LLM API 단독 호출 아키텍처 간의 정확도, 추론 지연시간, 일일 환산 비용의 격차를 정량적으로 비교한 시뮬레이션이다.

import os
# 백그라운드 렌더링 시 OpenMP 멀티스레딩 데드락(멈춤 현상) 방지
os.environ["OMP_NUM_THREADS"] = "1"
os.environ["OPENBLAS_NUM_THREADS"] = "1"

import time
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.metrics import f1_score, roc_auc_score

# 크로스 플랫폼 폰트 설정 (영문 라벨 표준화 및 마이너스 기호 깨짐 방지)
plt.rcParams['axes.unicode_minus'] = False

# 1. 불규칙한 결정 경계와 노이즈 피처를 가진 엔터프라이즈 정형 데이터 생성 (10,000건, 30개 피처)
# 유효 피처 10개, 다중공선성 피처 5개, 순수 노이즈 피처 15개 (이상치 비율 5%)
X, y = make_classification(
    n_samples=10000,
    n_features=30,
    n_informative=10,
    n_redundant=5,
    n_clusters_per_class=3,
    weights=[0.95, 0.05],
    flip_y=0.01,
    random_state=42
)

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, stratify=y, random_state=42
)

# 2. 전통적 트리 기반 모델 (HistGradientBoosting / LightGBM 계열) 학습 및 추론 시간 측정
model_gbdt = HistGradientBoostingClassifier(max_iter=100, random_state=42)
model_gbdt.fit(X_train, y_train)

start_time = time.perf_counter()
y_prob_gbdt = model_gbdt.predict_proba(X_test)[:, 1]
y_pred_gbdt = (y_prob_gbdt > 0.5).astype(int)
gbdt_elapsed_ms = (time.perf_counter() - start_time) * 1000  # 전체 3,000건 추론 시간(ms)

gbdt_auc = roc_auc_score(y_test, y_prob_gbdt)
gbdt_f1 = f1_score(y_test, y_pred_gbdt)
gbdt_latency_per_req_ms = gbdt_elapsed_ms / len(X_test)

위 실험 결과가 보여주듯, 30개의 피처를 가진 정형 데이터 3,000건을 트리 기반 모델로 추론하는 데 걸리는 시간은 수 밀리초(ms)에 불과하며, ROC-AUC 역시 0.95 이상의 높은 판별력을 즉시 확보한다. 반면 하루 1,000만 건의 이벤트를 단일 LLM에 직결하면 일일 API 비용만 1만 3천 달러(한화 약 1,800만 원)를 초과하고, 건당 1초가 넘는 지연시간으로 인해 실시간 모니터링 큐(Queue)가 마비된다.

반대로 전통적 ML 모델만 단독으로 사용하는 아키텍처(Traditional ML Only) 역시 명확한 한계를 지닌다. 모델이 이상 확률 0.94라는 스칼라(Scalar) 숫자를 뱉어냈을 때, 현장 운영자나 엔지니어는 “그래서 왜 이상이 발생했고, 매뉴얼의 어느 조항에 따라 어떤 조치를 취해야 하는가?”를 파악하기 위해 다시 수십 분간 대시보드와 로그 테이블, 장애 대응 문서를 뒤져야 하기 때문이다. 바로 이 지점에서 두 세계의 결합이 요구된다.

1.3 패러다임의 이동: 단일 모델에서 복합 AI 시스템(Compound AI Systems)으로

2024년 2월, UC 버클리 인공지능연구소(BAIR)의 Matei Zaharia, Ion Stoica 교수 연구진은 “The Shift from Models to Compound AI Systems”라는 선언적 아티클을 통해 현대 AI 엔지니어링의 방향성을 명쾌하게 정의했다. 당시 최고 수준의 성취를 보여준 AI 시스템들을 해부해 보니, 그 어떤 시스템도 거대 모델 하나의 단독 추론(Zero-shot/Few-shot inference)으로 결과를 내지 않았다는 사실이다.

시스템 명칭 해결 과제 내부 복합 아키텍처 구성 (Compound Architecture)
AlphaCode 2 (DeepMind) 프로그래밍 경진대회 문제 해결 LLM 샘플링(최대 100만 개 후보 생성) \(\rightarrow\) 코드 실행 및 테스트 필터링 \(\rightarrow\) 클러스터링 모델 \(\rightarrow\) 스코어링 모델을 통한 최종 코드 선택 (전체 성능의 대부분이 사후 필터링과 결합 구조에서 발생)
AlphaGeometry (DeepMind) 국제수학올림피아드 기하학 증명 신경망 언어 모델(직관적 보조선 생성) + 기호 연역 엔진(Symbolic Deduction Engine, 규칙 기반 엄밀한 증명)의 교차 루프
엔터프라이즈 자율 진단 시스템 실시간 이상 감지 및 원인 분석 리포팅 시계열/정형 ML·DL(이상 감지 트리거) + XAI 추출기(SHAP 기여도) + Hybrid RAG(장애 매뉴얼 검색) + LLM Agent(종합 추론 및 리포트 생성)

이 아키텍처 패러다임은 인지과학자 대니얼 카너먼(Daniel Kahneman)이 정립한 인간의 두 가지 사고 체계와 정확히 대응된다.

  1. System 1 (빠르고 직관적인 무의식적 패턴 감지 \(\rightarrow\) 판별·예측형 ML/DL): 고차원의 수치 데이터와 실시간 스트림을 밀리초 단위로 훑으며 정상 분포에서의 이탈(Anomaly)이나 위험 확률을 즉각 계산한다. 비용이 극도로 저렴하고 결정론적(Deterministic)이므로 전체 트래픽의 99%를 전방에서 방어한다.
  2. System 2 (느리고 분석적인 숙고적 추론 \(\rightarrow\) LLM 에이전트): System 1이 경보를 울렸을 때만 호출된다. 이상을 유발한 핵심 피처(XAI)를 넘겨받아 과거 이력 DB를 조회하고, 비정형 운영 매뉴얼을 검색(RAG)하여 원인을 논리적으로 추론한 뒤 인간 관리자가 즉시 승인할 수 있는 조치 계획서를 작성한다.
TipArchitecture Blueprint: 단일 LLM 구조 vs. 하이브리드 복합 AI 아키텍처

단일 LLM에 모든 원시 데이터를 주입하는 안티패턴(Anti-pattern)을 걷어내고, 전통적 ML/DL 모델을 전방 트리거(Trigger)이자 설명 가능한 오라클 도구(Oracle Tool)로 배치한 표준 복합 AI 아키텍처의 데이터 흐름은 다음과 같다.

1.4 단일 LLM 아키텍처의 실패 해부와 하이브리드 전환

현업에서 데이터 사이언티스트가 에이전트 개발 조직에 합류했을 때 가장 먼저 수행해야 할 역할은, 무분별하게 LLM 프롬프트로 처리되고 있는 수치·판별 로직을 발라내어 구조화된 모델과 도구(Tool)로 분리하는 작업이다.

실제로 수치 데이터를 마크다운 표나 JSON 문자열로 직렬화(Serialization)하여 LLM에 직접 판단을 맡겼을 때 어떤 실패가 발생하는지 실제 로그를 통해 살펴보자.

WarningEval Lab & Failure Log: 원시 수치 프롬프팅의 실패 사례와 교정

실험 시나리오: 25개의 네트워크 장비 메트릭(CPU 부하, 패킷 손실률, 지연시간 분산 등)을 바탕으로 다변량 이상 여부를 판별하고 원인을 지목하는 과제.

[실패 로그 — Raw Numerical Prompting (Monolithic LLM)] - 입력 방식: 최근 60분간의 25개 피처 시계열 배열(총 1,500개 부동소수점 수치)을 프롬프트에 텍스트로 삽입. - 발생한 오류 모드(Error Mode): 1. 컨텍스트 중간 소실(Lost in the Middle): 프롬프트 중간(32분~40분 구간)에 위치한 미세한 패킷 손실률 급증 패턴을 무시하고, 프롬프트 맨 마지막 줄의 정상 수치만 참조하여 "현재 모든 지표가 정상 범위 내에 있음"으로 오판(False Negative). 2. 산술 환각(Arithmetic Hallucination): 평균 지연시간이 14.2ms에서 19.8ms로 39.4% 증가했음에도, "약 2배 이상 폭증하여 임계치를 초과했다"며 근거 없는 수치를 생성. 3. 비일관성(Non-determinism): 동일한 수치 프롬프트를 temperature=0.0으로 5회 반복 호출했음에도 부동소수점 반올림 해석이 흔들리며 판정 결과가 바뀜.

[교정 결과 — ML Trigger + XAI Payload 주입 (Compound AI)] - 개선 방식: 원시 시계열 배열은 오토인코더(Autoencoder)와 GBDT 모델이 처리하고, 에이전트에게는 다음의 압축된 구조화 JSON만 전달한다. json { "anomaly_detected": true, "anomaly_score": 0.942, "threshold": 0.750, "top_contributing_features_shap": [ {"feature": "packet_loss_variance_10m", "value": 0.084, "normal_range": "0.001~0.015", "shap_impact": "+0.41"}, {"feature": "retransmission_rate", "value": 4.2, "normal_range": "0.1~0.8", "shap_impact": "+0.28"} ] } - 정량적 개선 효과: - 입력 토큰 수: 3,800 토큰 \(\rightarrow\) 145 토큰 (96.2% 절감) - 원인 피처 지목 정확도(Trajectory Accuracy): 54.0% \(\rightarrow\) 98.5%

이처럼 기존에 개발해 온 머신러닝과 딥러닝 모델은 에이전트 시대에 폐기해야 할 유물이 아니다. 오히려 LLM의 수리적 취약점과 비용 병목을 완벽하게 보완해 주는 고정밀 감각 기관(Sensor & Oracle)이다. 앞으로 이어질 장들에서는 언제 단순 워크플로우를 쓰고 언제 자율 에이전트를 도입해야 하는지 의사결정 기준을 세우고, 전통적 ML/DL 모델을 표준 프로토콜(MCP)로 캡슐화하여 에이전트 런타임에 결합하는 구체적인 엔지니어링 기법을 하나씩 구현해 나간다.
